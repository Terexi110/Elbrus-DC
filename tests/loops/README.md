# Тесты восстановления циклов

`loops.c` содержит 16 функций, по одной на каждую форму цикла: `for` вверх, вниз и с шагом, константное число итераций, проход указателем, `while` по строке, `while` с ветвлением (Коллатц), `do-while`, вложенные `for`, `break`, `continue`, вызов в теле, `for(;;)` с выходом из середины, запись в память (`fill`) и копирование (`copy_arr`).

`unroll.c` содержит 13 циклов, которые lcc разворачивает (индекс в значении, `long`-накопитель, счёт вниз, условие в теле, `short`/`char`, изменение на месте, шаг 2, начало не с нуля, два накопителя, вложенные циклы, расширение `int` → `long`, `double`), уровни `-O1..-O3`.

Сборка (lcc на машине пользователя):

    for O in 0 1 2 3; do lcc -O$O -c loops.c -o loops_O$O.o; e2k-linux-objdump -dr loops_O$O.o > loops_O$O.dis; done
    for O in 0 1 2 3; do ../../dc.sh loops_O$O.o -o loops_O$O.dc.c; done
    for O in 1 2 3; do lcc -O$O -c unroll.c -o unroll_O$O.o; e2k-linux-objdump -dr unroll_O$O.o > unroll_O$O.dis; done

## Дифференциальная проверка

    python3 tests/loops/difftest.py            # все наборы
    python3 tests/loops/difftest.py tests/t2_O2.o

Скрипт компилирует обычным `gcc` (x86) исходник и декомпилированный код (функции переименованы в `*_dc`). Затем он вызывает обе версии на 400 случайных входах и сравнивает возвращаемые значения и записанные буферы. Для `copy_arr` и `saxpy` проверяются и перекрывающиеся массивы (`dst = src ± d`): так проверяется путь с `%MLOCK`. Функции, в выводе которых остались `__e2k_*` или `__asm__`, не тестируются и выводятся отдельным списком. Мутационная проверка (испортить шаг цикла в выводе) ловится сразу.

Наборы: `loops_O0..O3`, `unroll_O1..O3`, `arch_O1/O3`, `t1_O0..O2`, `t2_O0..O2`, `structs_O0..O3`, `structs2_O0..O3`.

Результат на текущей версии: 312 сочетаний «функция × уровень», 130 800 прогонов, расхождений 0. Не проверяются `dec_chars` и `sum_xor` на `-O3` (в выводе остались `__e2k_*`) и `dsum` из `unroll.c` (на `-O2` указатель-параметр и результат `double` делят `%dr0` через охраняемые записи, прототип получается `double dsum(double a1, ...)`).

Для сравнения, исходная версия декомпилятора:
- на -O2 и -O3 давала проверяемый код только для 2 функций из 16 в loops;
- расходилась с исходником в `t1 -O2` (220 из 4400), `ll -O2` (знак у `a / 7`) и `fib -O3`.

## Что делает декомпилятор с циклами

**Структурирование** (`e2kdc/loops.py`, проходы по AST после `structure.cleanup`):

- `sink_temps`: `t = E(i); ++i; ... a[t] ...` превращается в `... a[E(i)] ...; ++i;`. Шаг не переносится через узлы с переходами внутри (`if (..) continue`).
- `sink_into_cond`: `do { p = x <= 1; ... } while (!p)` превращается в `while (x > 1)`. Через шаги `i += c` выражение переносится со сдвигом.
- `unguard`: `i = 0; if (C[i:=0]) do B while (C)` превращается в `while (C) B`.
- `flip_tail`: `if (c) { A; continue; } break;` превращается в `if (!c) break; A`.
- `make_for`: `i = X; while (C(i)) { B; i += c; }` превращается в `for (i = X; C; i += c) B`.
- `assume_after_exit`: после `if (C) return ...;` условие `C` считается ложным в остальной части списка (и во вложенных телах), внутри `if (C) {A} else {B}` оно истинно в `A` и ложно в `B`. Действует, пока переменные `C` не переопределены.
- `sink_into_exit`: `if (C) x = E; ...; if (C) return x;` превращается в `if (C) return E;`, если между ними `x`, `C` и `E` не меняются и `x` не читается.
- `fold_returns`: `v = X; return v;` превращается в `return X;`.
- `coalesce_copies`: `t = E; v = t;` превращается в `v = E`, если `t` больше нигде не встречается.
- `drop_overwritten`: `x = E; ...; x = F` без чтения `x` между ними: первое присваивание убирается (обычно это загрузка, оставшаяся от предикатного пути).
- После всех проходов `if (1)`/`if (0)` раскрываются, код после перехода и неиспользуемые метки удаляются (`structure.final_tidy`).

**Свёртка развёрнутых циклов** (`e2kdc/reroll.py`, после `predicate.py`). На `-O2` lcc повторяет тело дважды и добавляет копию для нечётного числа итераций:

    v3 = n > 0 ? n : 1;  v7 = (unsigned)v3 >> 1;  t = 0;
    if ( v7 != 0 ) { t = 2 * v7; for ( i = 0; i < v7; ++i ) s = a[2*i] + a[2*i+1] + s; }
    if ( v7 << 1 != v3 ) s = s + a[t];

Проход печатает это как `for ( i = 0; i < n; ++i ) s += a[i];`. Тело одной итерации S(J) берётся из хвоста (индекс J = 2M), а развёрнутое тело должно делать то же, что S(2i); S(2i+1): обе последовательности выполняются символически (переменные и записи в память), значения сравниваются с точностью до линейной арифметики и перестановок `+ ^ | &` для целых. Условие хвоста должно означать «N нечётно» при M = N >> 1, значения вспомогательных переменных на путях M == 0 и M != 0 должны совпадать, N должно быть неотрицательным. Принимаются и формы без `if (M != 0)` (если из условий выше следует N >= 2), `N & -2` вместо `2 * M`, переменная `t = 2 * i` из тела (её значение после цикла берётся из последней итерации) и загрузка хвоста, вынесенная компилятором между циклом и хвостом. После свёртки:

- `for (i = 0; i < (n - 1) / d + 1; ++i) S(d * i)` → `for (i = 0; i < n; i += d) S(i)` (деление сдвигом или умножением на магическую константу, `n >= 1` по фактам);
- `for (i = 0; i < u - o; ++i) S(i + o)` → `for (i = o; i < u; ++i) S(i)`;
- две версии одного кода под чистым условием (`if (C) { A; return; } A;`, `if (C) A else A`), которые компилятор делает для возможно перекрывающихся массивов, сливаются в одну.

Не сворачиваются версии `-O3` с разворотом в 4 раза и хвостами 2 + 1, с несколькими накопителями и широкими загрузками (`for_up`, `copy_arr`, `fill` в `-O3`).

**Счётные циклы** (`e2kdc/ivcanon.py`, после структурирования). Цикл со счётчиком `lc` (условие содержит `lc != 0`, шаг один `--lc`) переписывается через общий индекс:

- указатели `p += c`, у которых начальное значение задано до цикла и которые не нужны после него, заменяются на `P0 + c*i`, а обращение `*(int *)(P0 + 4*i)` печатается как `((int *)P0)[i]` (`index_form`);
- `lc` становится индексом `i` (имена `i`, `j`, `k`, `i2`…), условие `lc != 0` превращается в `i < N`;
- если по фактам на входе (`Facts`: условия охватывающих `if`, константы, `x > 0 ? x : 1`) доказано `N >= 1`, получается `for (i = 0; i < N; ++i)`, иначе `i = 0; do { ...; ++i; } while (i < N)`.

**Векторизация** (`e2kdc/devec.py`, после структурирования):

- Редукции. Аккумуляторы `a = __paddw(a, X)` с горизонтальной суммой `h = __paddw(r, r >> 32)`, у которой читается только `(int)h`, заменяются на `int`, равный сумме двух половин: `a += X.lo + X.hi`. Сумма по модулю 2^32 одна и та же.
- Отображения. Переменная, все определения которой упакованные операции (`__pfadds/pfsubs/pfmuls`, `__paddw/psubw`, `__pcmpgtw/pcmpeqw`), а чтения либо операнды таких же операций, либо 64-битная запись, либо явное извлечение половины (`(int)v`, `(int)(v >> 32)`), делится на две скалярные `v_0`, `v_1` (`float` или `int`). 64-битная запись становится двумя 32-битными. Если загрузки старшей половины могут читать только что записанную младшую (адреса не отличаются на константу >= 4), старшая половина сначала вычисляется во временную `vlN`: порядок «все чтения до записи», как у исходной 64-битной операции, сохраняется. `saxpy -O3`: `((int *)a4)[4*i2] = __bitcast_int(a * x[4*i2] + y[4*i2])` и т. д.
- `pshufb` с константным управлением, где все байты берут один и тот же байт источника, печатается как `(unsigned char)x * 0x101010101010101` (заполнение в `fill`).

**Константы по достигающим определениям** (`analysis.const_intr_args(F, all_vars=True)`, в конце `optimize`): чтение переменной, у которой все достигающие определения дают одну константу, заменяется константой. Так бывает, когда web склеен общим регистром: `v5 = 0` на пути к ядру и `v5 = n << 2` на другом. Если достигающее определение — дешёвое выражение от параметров, которые нигде не переопределяются (`(unsigned char)a2`, `a2 > 0`), подставляется оно.

**Перенос охраняемого присваивания** (`structure.sink_guarded_far`, на CFG): `if (g) x = E` в блоке `B0` переносится без охраны в блок `T`, если `T` доминируется `B0`, на пути к `T` известно, что `g` истинно (условия ветвлений на цепочке доминаторов, раскрытие однократно определённых предикатов), все чтения `x` доминируются `T`, а между `B0` и `T` не меняются `x`, переменные `g` и `E` (и нет записей в память, если `E` читает память). Убирает лишние параметры вроде `a5` в `for_continue -O3`.

**Обратное if-conversion** (`structure.sink_guarded`, до структурирования): `if (p) S` в блоке, который заканчивается ветвлением по `p`, переносится без охраны в начало соответствующей ветки. Получается `if (!p) return 0;` вместо `if (!p) a1 = 0; if (!p) return a1;`. Параметром считается только регистр, живой на входе функции.

**Аппаратные циклы** (`e2kdc/lift.py`):

- `rwd X, %lsr` поднимается как `lc = lcnt + ecnt` и `pc = pcnt`. `alc` превращается в `lc -= 1` и `pc -= (pc != 0)`. `%NOT_LOOP_END` становится `lc != 0` (после декремента), `%LOOP_END` — `lc == 0`, `%pcntN` — `pc <= N`.
- Записи в ШК с `loop_mode` (HS.lm) охраняются условием qemu (`e2k_translate_calc_ld_st_loop_conds`): `semc || pcnt == 0 && !(loop_end && strmd <= k)`, где `loop_end = vlc && lcnt < 2 && ecnt == 0`, а `k` — номер записи среди записей последней итерации (первая запись ШК — `stl`, вторая — `str`; уменьшение `strmd` после каждой записи в конце цикла учтено в `k`, `Lifter._scan_loop_mode`). Поля `vlc`, `strmd`, `semc` берутся из того же `rwd`. Условие — `Intr st_enbl`, оно сворачивается в `simplify`: lcc ставит `strmd` равным числу записей за итерацию, поэтому на всех тестах условие истинно. Если `strmd` меньше, получится `if (lc > 1) ...` (последняя итерация не пишет), если `pcnt` не константа — `__e2k_st_enbl(...)` в выводе.
- `abn`: параллельный сдвиг вращаемого окна `N(i) := N(i-2)` при статических именах. `abp`: `pred[i+1] := pred[i]`.
- Условия `ct` и предикатного `call` читают состояние до ШК: регистры, которые ШК перезаписывает, снимаются в начале ШК.
- `%MLOCK` = 1. Путь по нему перевычисляет значение из перечитанной загрузки (`mas` с `mod 3`), а при отсутствии конфликта результат тот же.
- AAU: `aaurw{s,d,q}` пишут `aad/aasti/aaincr`; `staa*`/`ldaa*` дают store/load по `aad + aasti + lit`; `incr` даёт `aasti += aaincr * размер`. `st* ... mas=0x..7` — служебная операция, не запись.
- APB: программа FAPB (ШК из `apb`, выбирается через `ldisp %ctpr2`) разбирается заранее. `bap` задаёт для каждой области базу `aad[d]`, смещение `aaind[ind] + disp` и шаг `fmt * aaincr[incr]`; `mova*` становится загрузкой `base + aaldi + ind`, `am=1` сдвигает `aaldi`.
- Упакованные операции (`paddw`, `psubw`, `pcmpgtw`, `pcmpeqw`, `pfadds/subs/muls`, `pshufb`) превращаются в функции-хелперы в заголовке, вывод компилируется. `insfd`/`getfd` с регистровой спецификацией: общая формула, которая сворачивается, если спецификация константна (`analysis.const_intr_args`).

**Снятие конвейеризации** (`e2kdc/depipe.py`, одноблочные циклы):

1. Символически вычисляются значения на конец итерации и находятся индукционные переменные `iv = iv + step` (шаг может быть инвариантом).
2. Для переменных, которые через цепочку копий выражаются через `iv`, выводится замкнутая форма, и она принимается, только если совпадает со значением из пролога (сравнение по модулю линейной арифметики).
3. Чтения заменяются замкнутой формой. Промежуточные определения (перечитанная загрузка) не трогаются. Форма с загрузкой не переносится через запись той же итерации: её значение вычисляется в начале итерации.
4. `rebase_ivs` переносит базу `iv` (смещения могут быть символическими).

DCE (`analysis.dce_live`) использует «сильную» живость по определениям.

## Найденные и исправленные ошибки (не только в циклах)

- `X_sub`/`X_rsub` (составные операции): порядок операндов был обратным, по qemu `X_sub = s3 - (s1 X s2)`, `X_rsub = (s1 X s2) - s3`. Ломалось деление на константу (`ll -O2`).
- Предикатный `call ? %pred` читал предикат после PLU той же ШК (`fib -O3`).
- Печать: `(unsigned int)x << 32` и `int + int` с 64-битным результатом теперь явно расширяются.
- Переменная с 32-битным float-определением и 64-битным определением (упакованная пара) получала тип float и теряла старшую половину (`saxpy -O3`).

## Не сделано

- Конвейеризованные рекуррентности остаются цепочками копий: `inf_loop -O3` (следующий `p[i]` загружается до проверки текущего), `while_cond -O3` (условие с предыдущей итерации), `saxpy -O3` при `n < 16` (значения вычисляются на 4 итерации вперёд, загрузки `x[k+4]` идут до записи `y[k]`). Свернуть их можно, только доказав, что загрузки не пересекаются с записями, а это знание сидит в проверке перекрытия до цикла.
- Многоблочных ядер конвейера в тестах нет: оставшиеся цепочки (выше) в одноблочных ядрах, `depipe` их не берёт по указанной причине.
- Подавление записей в прологе (`pcnt != 0`) моделируется, но lcc в тестах всегда пишет `pcnt = 0` (пролог разворачивается явно), так что на реальном прологе это не проверено.
- 64-битные «хвосты» векторных циклов (`v = *(long *)p; s += (unsigned)v + (unsigned)(v >> 32)`) не делятся на две 32-битные загрузки.
