# Настоящие программы

`survey.py` декомпилирует e2k-программы целиком и считает, что осталось недоделанным. Эталона нет: числа нужны, чтобы видеть тренд между версиями.

    python3 tests/real/survey.py                     # утилиты из $LCC/fs/usr/bin
    python3 tests/real/survey.py -o /tmp/out a b     # свои файлы, вывод .c в /tmp/out
    python3 tests/real/survey.py -j 1                # без процессов-исполнителей (по умолчанию по одному на CPU)

`LCC` по умолчанию `/opt/mcst/lcc-1.31.05.e2k-v3.4c.linux-6.1`. Набор по умолчанию: getconf, pcprofiledump, pldd, zdump, getent, gencat, makedb, sprof. Это утилиты glibc из sysroot lcc, собранные как PIE, с символами.

Колонки: функции, отказы (исключение или бюджет времени), функции с `__e2k_*`/`__asm__`, число `goto`, ошибки `gcc -fsyntax-only` (предупреждения выключены), секунды.

## Результат

| | v6 | v7 | v8 | v9 | v10 |
|---|---|---|---|---|---|
| файлов с выводом | 6 из 8 (gencat, makedb: `RecursionError`) | 8 из 8 | 8 из 8 | 8 из 8 | 8 из 8 |
| функций | 62 | 97 | 97 | 97 | 97 |
| отказов | 5 (+ getconf зависал) | 0 | 0 | 0 | 0 |
| функций с `__e2k_*` | 52 | 12 | 12 | 12 | 12 |
| `goto` | — | 402 | 343 | 343 | 343 |
| строк `if ( pN ) x = ...;` | — | 2794 | 358 | 358 | 358 |
| ошибок gcc | — | 68 | 59 | 59 | 59 |
| секунд (2 ядра) | | | | 95 | 24 (`-j 1`: 34) |

v8 — обратное преобразование предикатного кода (`e2kdc/predicate.py`): операторы под общим
условием собираются в один `if`, условие и его отрицание становятся if / else, выходы
выносятся вперёд. v9 — свёртка развёрнутых циклов (`e2kdc/reroll.py`); в этих утилитах
развёрнутых циклов нет, вывод совпадает с v8 с точностью до номеров переменных.
v10 — скорость: инкрементальные def/use и рабочий список в `propagate`, параллельные
проходы по функциям (`e2kdc/parallel.py`). Вывод совпадает с v9 с точностью до номеров
переменных и структур. Те номера в v9 зависели от раскладки памяти (обход множеств
объектов с хэшем по адресу), теперь вывод детерминирован и не зависит от `-j`.

Что дало разницу:

- `rrd %ip` → адрес ШК, `ip + k` → адрес в `.got`/`.rodata`/`.data`; загрузка из `.got` → символ из динамической релокации. Вызовы через `.got` получили имена, строки и глобалы — свои имена.
- `%ctpr` на слиянии путей: значение, подготовленное на одном пути, сохраняется; несколько значений — набор кандидатов; мёртвый fall-through после `ct ? p; ct ? ~p` не учитывается.
- Прототипы glibc (`error`, `dcgettext`, `__errno_location`, `localtime_r`, `open64`…) задают число аргументов уже при разборе вызова; вызов void-функции не даёт результата; функция, которую зовут с разным числом аргументов, объявляется с `...`.
- Устойчивость: бюджет времени на функцию, изоляция сбоев по функциям и этапам, ограничение циклов до неподвижной точки, нет бесконечной рекурсии в реестре структур (взаимные ссылки A → B → A) и в разборе аргумента `p + i`.

Что осталось (59 ошибок gcc): в основном типы — сложение двух указателей и указатель в индексе (параметр и результат в одном регистре через охраняемые присваивания), у нескольких функций файла вызов передаёт больше аргументов, чем у определения параметров (`show` в zdump), три `goto` на метки, которые не напечатаны (sprof). `__e2k_*`: `__e2k_va_area` (тела variadic-функций), `movep` в PLU, `merge` с адресом, чтение `%lsr`, два непрямых перехода и два вызова, у которых на разных путях разные функции в `%ctpr`.
