# Тесты архитектурных особенностей e2k

`arch.c` — 10 функций, каждая заставляет lcc задействовать конкретный механизм Эльбруса.
Сборка (через обёртку, т.к. lcc ищет себя в /opt/mcst):

    lcc -O1 -c arch.c -o arch_O1.o     # «как обычный процессор»: ветвления
    lcc -O3 -c arch.c -o arch_O3.o     # «как Эльбрус»: предикаты, спекуляция, конвейер
    e2k-linux-objdump -dr arch_O3.o > arch_O3.dis
    python3 feat.py arch_O1.dis arch_O3.dis   # таблица: какие механизмы найдены

## Аналогия со столовыми (`canteen`)

-O1 — обычный процессор: проверили условие, переход (`ct %ctpr1 ? ~%pred0`) в одну из
«столовых», вторая ветка не исполняется. Неверно предсказанный переход = школьники разворачиваются.

-O3 — Эльбрус: ни одного перехода, кроме `return`. Обе ветки считаются одновременно
в разных каналах одной широкой команды, нужный результат «открытой столовой» выбирает предикат:

    cmpesb,0 %r0, 0x0, %pred0            ; какая столовая открыта
    shls,1,sm %r2, 0x2, %g16             ; путь во 2-ю:  b*4
    shls,2,sm %r1, 0x1, %g17             ; путь в 1-ю:   a*2      (параллельно!)
    adds,0,sm %g16, %r2, %g16            ; b*5
    adds,1,sm %g17, %r1, %g17            ; a*3
    subs,0,sm %g16, 0x2, %g16 ? %pred0   ; итог 2-й, если она «открыта»
    adds,1,sm %g17, 0x7, %g16 ? ~%pred0  ; итог 1-й

Декомпилятор сворачивает это обратно: `v4 = a1 == 0 ? a3 * 5 - 2 : a2 * 3 + 7;`

## Что проверяет каждая функция (результат lcc 1.31, -O3)

| функция   | механизм                                   | что искать в дизассемблере |
|-----------|--------------------------------------------|----------------------------|
| canteen   | предикатное исполнение (if-conversion)     | `? %pred`, нет `ct %ctpr1` |
| canteen3  | логика предикатов в PLU                    | `pass`, `landp`, `@p0..@p6` |
| spec_load | спекулятивная загрузка до проверки `p!=0`  | `ldw,5,sm` **перед** `cmpedb` |
| wide      | широкая команда, 6 ALU-каналов             | `,0`..`,5` в одной ШК |
| saxpy     | программная конвейеризация + APB/AAU       | `loop_mode`, `%NOT_LOOP_END`, `abn/alc`, `aaurw`, `staa` |
| dot       | вращающиеся регистры                       | `%b[N]`, `setbn`, `abn` |
| fib       | регистровые окна, предикатный вызов        | `call ... wbs = N ? %pred2`, аргументы в `%b[]` |
| clamp_abs | цепочка выборов без переходов              | несколько `? %pred` подряд |
| find      | цикл с двумя выходами, спекуляция          | `ld*,sm`, `pass`/`landp` |
| fsel      | выбор в FP-каналах                         | `fmuld`, `faddd` под предикатами |

`-O1` против `-O3`: canteen 10 → 5 ШК, canteen3 18 → 8 ШК (до 10 операций в одной ШК).

## Состояние декомпилятора на этих тестах

Проверяется `python3 tests/loops/difftest.py` (сравнение с исходником на случайных входах).

Все 10 функций на -O1 и -O3 совпадают с исходником, низкоуровневых конструкций в выводе нет. На -O3 это включает:
- конвейеризованные `dot` и `find`, которые сворачиваются в обычный цикл;
- `saxpy` с APB и проверкой перекрытия массивов. Упакованные `pfmuls`/`pfadds` разложены на скалярные `float` (по 4 элемента за итерацию в выровненном ядре), счётчики переписаны в `for (i2 = 0; i2 < n; ++i2)`. Ветка `n < 16` остаётся конвейером с копиями: загрузки на 4 итерации вперёд нельзя перенести за записи без знания о неперекрытии;
- `fib`: раньше ошибка была в условии предикатного вызова, который читал `%pred` после PLU той же ШК.

Подробности механизмов — в `tests/loops/README.md`.
