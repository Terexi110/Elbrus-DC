# Тесты распознавания структур

`structs.c` содержит 12 функций, по одной на каждый способ работы со структурой:

- поля разных типов (`pt`: `int`, `int`, `long`), запись полей, копирование и сравнение через два указателя;
- выравнивание (`mix`: `char`, `short`, `int`, `double`, `long`);
- список (`node` с указателем на ту же структуру), обход `while` и `for`;
- массив внутри структуры (`buf`: `len`, `data[]`);
- массив структур (`rec`): поиск, сумма произведений полей, обмен полей;
- вложенная структура (`outer` с `inner`).

`structs2.c` (14 функций) проверяет то, чего в первом наборе не было:

- указатели на указатели: `char **`, `struct node **` (вставка в голову списка), `int **` (матрица из строк);
- вложенные структуры, которые передаются в другую функцию (`inner_sum(&o->in)`, `inner2_sum(&o->in)`);
- массив фиксированной длины в конце структуры (`buf_clear`, `buf_last`);
- структура на стеке (`pt_local`) и глобальные структура и массив структур (`gpt`, `gtab[16]`).

Сборка на машине пользователя:

    LCC=/opt/mcst/lcc-1.31.05.e2k-v3.4c.linux-6.1 tests/structs/build.sh            # оба набора
    LCC=/opt/mcst/lcc-1.31.05.e2k-v3.4c.linux-6.1 tests/structs/build.sh structs2   # только второй

Проверка: `python3 tests/loops/difftest.py tests/structs/structs*_O*.o` (входит в общий набор) и `python3 tests/sigcheck.py`.

## Как это работает (`e2kdc/structs.py`)

Указатели объединяются в классы: копии, `q = p + i*K`. По загрузкам и записям через указатели класса собираются пары (смещение, тип).

- **Массив структур.** Указатель индексируется как `p + i*K + c` или шагает `p += K`, и `K` больше размера обращения. Тогда это массив `K`-байтовых структур. Шаг развёрнутого цикла (`16*i` вместе с хвостом `8*j`) сводится к общему периоду, если раскладка повторяется. Индекс вида `(long)(2*i + 1) * 4` сначала приводится к `(long)i * 8 + 4` (`lin`). Это точно, если индекс `int` не переполняется, а в исходнике такое переполнение не определено.
- **Одна структура.** Шага нет, но есть поля разных размеров, поле-указатель на тот же класс (`n = n->next`) или индексируемый массив после скалярных полей (`b->len`, `b->data[i]`).
- **Что не считается структурой.** Указатель, который индексируется от начала (`p[i]`), указатель на известный стековый или глобальный массив, развёрнутый побайтовый цикл (`d[2*i]`, `d[2*i+1]`), единственное скалярное поле.

Поля называются по смещению (`f0`, `f4`, `f8`…), промежутки заполняются `char _pN[k]`, поэтому напечатанная раскладка совпадает с исходной байт в байт. Одинаковые раскладки получают одно имя на весь файл. Раскладка, которая без конфликтов укладывается в уже известную, сливается с ней: `list_len` видит только `next`, но получает ту же `struct s3`, что и `list_sum`. Обращение, которое не совпадает с полем (64-битная векторная загрузка поверх двух `int`), печатается с явным приведением.

- **Массив байтов в поле.** Восемь и больше однобайтовых полей подряд печатаются как `char fN[k]` (полностью развёрнутый цикл по `data[20]` на -O3).
- **Смещение в отдельной переменной.** Переменная, которая равна `K * x` во всех определениях и складывается с указателем только в адресах, хранит байтовое смещение. `rescale_offsets` заменяет её индексом (`v = i` вместо `v = i << 3`, обращения `p + v*8`). Это работает и для переменной с шагом `v += 8`, и для цепочки копий (`v11 = v73; v73 = v11 + 8`): у каждой переменной свой `K`, он считается неподвижной точкой. Байтовые обращения не трогаются, там смещение уже индекс.

Печать (`emit.Printer.field_access`, `struct_access`): `p->f4`, `p[i].f0`, `p->f4[k]`, `p->f4.f0` для вложенной структуры, адресная арифметика масштабируется на размер структуры (`a1 + v4`), `&p->f4` для адреса поля.

## Указатели на указатели (`types.py`)

Если через указатель `p` загружается значение, а через него самого потом идёт обращение к памяти, у `p` тип элемента — указатель (`VarInfo.ptr_elem`). Так получаются `char **a1` (`*a1[i]`), `int **a1` (`a1[i][j]`). Указатель, через который записываются и читаются только 8-байтовые указатели со смещением 0, тоже не структура, а массив указателей: `struct s7 **a1` в `push`. Сумма двух 64-битных значений без констант считается `long` (`mat_sum` возвращает `long`).

## Межпроцедурные типы (`interproc.py`)

Подготовка всех функций файла (`prepare`) идёт до печати, между ними `link_types`:

- тип параметра вызываемой функции переходит на аргумент и наоборот (`outer2_total` передаёт `&a1->f4` в `inner2_sum(struct s3 *)`);
- аргумент `p + c`, где `p` — структура `T`, а параметр — структура `S`, делает поле `c` структуры `T` вложенной структурой `S` (`struct s4 { int f0; struct s3 f4; ... }`); если параметр — указатель на скаляр, поле становится массивом (`short f4[2]` у `outer`);
- `&local` в аргументе со структурой делает переменную на стеке структурой (`struct s1 local_10;`, обращения `local_10.f8`);
- глобальные символы с полями разных типов или с шагом становятся глобальными структурами (`extern struct s1 gpt;`, `extern struct s3 gtab[16];` — длина по размеру символа), однородные — массивами (`extern int gtab[32];`, `gtab[6]`).

Слияние раскладок из разных функций разрешено только при сильном признаке: общее поле-указатель или принадлежность одному массиву. Иначе две несвязанные структуры одного размера не склеиваются.

Обращения к глобальным данным собираются по всему файлу (`Context.global_use`), поэтому `gtab[0]` не печатается как скаляр `gtab`, даже если первое встреченное обращение — по смещению 0.

## Спекулятивные загрузки

lcc на -O2/-O3 выносит загрузку `n->next` выше проверки `n != 0` (`ld*,sm`). На e2k недопустимый адрес даёт диагностическое значение вместо исключения, а в C такая загрузка упадёт. Загрузка с флагом `sm` через указатель, который где-то в функции сравнивается с 0 (или копию такого указателя), печатается как `__SPEC(p, p->f8)`. Макрос возвращает 0 для адресов меньше 4096.

## Результат

difftest: все функции обоих наборов на -O0..-O3 совпадают с исходником (structs — по 4800 прогонов на уровень, structs2 — по 5600). Сигнатуры: structs 128 из 128, structs2 136 из 140.

Что не совпадает с исходником:

- `inner_sum`: `struct inner { short a; short b; }` печатается как `short *` — структура из одинаковых полей по коду неотличима от массива;
- `buf_clear -O2`: массив в конце структуры остаётся `char f4[]`, длина 20 видна только из границы цикла;
- `gtab_find -O3` (цикл развёрнут полностью, все смещения константные): `gtab` печатается как `int gtab[32]`, а не массив структур `{int; int}`.
