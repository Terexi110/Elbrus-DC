# Elbrus-DC: декомпилятор e2k в псевдо-C

`e2kdc` превращает ELF-файлы Эльбруса (e2k: `.o`, исполняемые, `.so`) в псевдо-C. Он написан на чистом Python 3 и не имеет внешних зависимостей. На вход принимает листинг `e2k-linux-objdump -dr`, сам ISA не декодирует.

## Запуск

```sh
./dc.sh tests/t2_O1.o                 # все функции
./dc.sh tests/t2_O1.o -f fact -f fib  # только выбранные
./dc.sh x.o --ir                      # дамп промежуточного представления
./dc.sh x.o --dis x.dis               # готовый листинг objdump вместо запуска
./dc.sh x.o --no-header -o x.c
./dc.sh prog --timeout 30             # бюджет на функцию и этап, с (0: без ограничения)
./dc.sh prog -j 1                     # без процессов-исполнителей (по умолчанию -j 0: по одному на CPU)
```

Вывод не зависит от `-j` и от раскладки памяти (проверено байт-в-байт). Если где-то перебирается множество объектов (`VarInfo`, `Struct`, блоков), его хэш — адрес, и порядок обхода меняется от запуска к запуску: такие множества надо держать в `dict` (упорядоченное множество) или сортировать. Проверка: прогнать вывод при разных раскладках памяти (создать перед запуском разное число объектов) и сравнить.

`dc.sh` выставляет `E2K_OBJDUMP=tests/e2k-linux-objdump` и запускает `python3 -m e2kdc`. objdump ищется в таком порядке: `--objdump`, затем `$E2K_OBJDUMP`, затем `e2k-linux-objdump` в `PATH`.

## Тулчейн (машина пользователя)

- lcc 1.31.05: `/opt/mcst/lcc-1.31.05.e2k-v3.4c.linux-6.1/bin`. **Не переносить**: lcc ищет компоненты (`ecf_opt64` и др.) относительно `/opt/mcst`.
- binutils 2.41 (порт e2k): `/mnt/llms/projects/elbrus/build/binutils/`. Утилиты там **без префикса** (`objdump`, `readelf`…). Каталог нельзя класть в `PATH` целиком, иначе он подменит системные x86-утилиты. Используются ссылки или копии с префиксом `e2k-linux-`.
- Исходники МЦСТ: `/mnt/llms/projects/elbrus/` (binutils `opcodes/e2k-dis.c`, `e2k-opc.h`; glibc, linux, gdb).
- qemu-e2k: `/mnt/llms/projects/qemu`. Семантика операций лежит в `target/e2k/tcg/translate-*.c`. Это эталон, когда неясно, что делает операция (поля `getf*`, `sxt`, `merge*`…).

Компиляция тестов: `e2k-linux-lcc -O1 -c t.c -o t_O1.o`. Если lcc лежит не в `/opt/mcst` (каталог смонтирован в другое место, как в Linux-VM рабочего стола Claude), пути к компонентам задаются явно: `L=<путь к lcc-1.31.05...>; $L/bin/lcc -B$L/lcc-home/1.31.05/e2k-4c-linux.cross/bin/ -B$L/binutils/bin/e2k-linux- -O2 -c t.c`.

## Устройство (`e2kdc/`)

Конвейер описан в `decompiler.py` (`Decompiler.decompile`):

1. `objdump.py`: запускает objdump и разбирает вывод в функции, широкие команды (bundles) и операции `Op(mnem, chan, flags, args, guard)`.
2. `elfread.py`: минимальный читатель ELF64 (секции, символы, RELA, строки).
3. `lift.py`: переводит одну широкую команду в IR. **Все операции ШК читают состояние до команды**, поэтому параллельные записи сериализуются через временные `t<addr>_<n>`. Операции PLU (`pass`/`andp`/`landp`) переупорядочиваются в порядок исполнения, а не кодирования.
4. `cfg.py`: строит CFG и отслеживает `%ctprN` (`disp` → `ct`/`call`). `%ctpr` переживает `call`, а условный вызов хранит свой guard (`ccond`). В исполняемом файле цель вызова ищется по адресу во всех секциях (`printf@plt` в `.plt`), безымянный код получает имя `sub_<адрес>`, вызов собственного начала — рекурсия. Состояние на входе в ШК: базы вращения, `%ctpr` и известные значения предикатов. `%ctpr`, подготовленный только на одном из путей, сохраняется; разные значения на разных путях дают `("multi", кандидаты)`, и вызов через него получает имя, если функция среди кандидатов одна (`call_desc`). Известный предикат делает `ct ... ? ~p` после `ct ... ? p` безусловным: его fall-through мёртв и не смешивает `%ctpr` чужого пути.
5. `analysis.py`: достигающие определения, webs (union-find), восстановление переменных и аргументов (`pure_entry`), типы, слияние `if(g)`/`if(!g)` в `Select`, propagate и DCE (`dce_live` — сильная живость по определениям, убирает циклы копий).
5a. `depipe.py`: снятие программной конвейеризации однoблочных циклов (замкнутые формы через индукционные переменные с проверкой по прологу, перенос базы `iv`).
6. `simplify.py`: свёртка констант, канонизация, правила вида `(x<<k)+x → x*(2^k+1)`.
7. `structure.py`: упрощение CFG (в том числе `fold_known_branches`, перенос охраняемых присваиваний `sink_guarded`/`sink_guarded_far`) и структурирование через ipdom (if/else, while/do-while, switch, `&&`/`||`, goto как запасной вариант). Затем на уровне AST: `loops.py` восстанавливает `for`/`while`, `devec.py` переводит упакованные редукции и отображения в скалярный код, `ivcanon.py` переписывает счётные циклы через индекс (`for (i = 0; i < n; ++i) ... p[i]`). Подробно в `tests/loops/README.md`.
7a. `predicate.py`: обратное if-conversion на AST. Операторы с общей охраной собираются в один `if`, условие и его отрицание становятся if / else, общие конъюнкты выносятся во вложенный `if`; условия упрощаются по известным фактам (охватывающие условия, отрицание условия раннего выхода, определения предикатов `p41 = p37 && p39`), рассуждение пропозициональное (атомы — предикаты и сравнения, маленький DPLL с бюджетом). Затем подстановка предикатов с одним использованием, `v = e; return v;` → `return e;`, выходы вперёд, одинаковые блоки выхода через `||`.
7b. `reroll.py`: свёртка развёрнутых циклов (тело дважды + хвост для нечётного числа итераций → один цикл; проверка символическим выполнением), шаг `i += d` по счёту `(n - 1) / d + 1`, начало `i = o` по счёту `u - o`, слияние двух одинаковых версий кода под чистым условием (проверка перекрытия массивов). Подробно в `tests/loops/README.md`.
8. `decompiler.py`: кадр стека (`local_N`, массивы), аргументы 9+ на стеке, jump tables в `switch`, глобалы и строки, финальные типы (`finalize_types`). Перед ними `analysis.split_webs` заново делит переменные на webs: регистр, переиспользованный под несвязанные значения (`%r0` = первый параметр, потом указатель, потом результат), получает отдельные переменные.
8a. `types.py`: восстановление типов. `demote_ints`: 64-битные переменные с 32-битными значениями становятся `int`/`unsigned int` (lcc считает `int` в 64-битных регистрах; предполагается отсутствие знакового переполнения, как в исходнике). `signedness`: `unsigned` по беззнаковым операциям (`/u`, `%u`, сравнения переменных; `x <u K` — проверка диапазона `switch`, не голос). `narrow_params`: `char`/`short` параметры. `func_pointers`: `int (*a1)()`. `float_vars`: регистры, которые только переинтерпретируются как float, становятся `float` (e2k передаёт float в общих регистрах), загрузки/записи — `float`. `address_bases` (на AST): 64-битная переменная, которая встречается только как база адреса загрузки или записи (`p + 4*i`), — указатель. `pointees` (на AST): тип элемента указателя по большинству обращений через него, с распространением по копиям и сравнениям; печать `p[i]`, `*p`, масштабированная арифметика (`emit.Printer.ptr_arith`). `apply_libc`: прототипы из `libc.py`.
8b. `structs.py`: структуры по обращениям через указатели (массив структур по шагу `p + i*K + c`, одна структура по полям разных размеров, полю-указателю на себя или массиву после скалярных полей). Поля `fN` по смещению, промежутки `char _pN[k]`, вложенные структуры и массивы-поля, одинаковые и совместимые раскладки сливаются в один тип на файл (`Registry`, только при общем поле-указателе или общем массиве). `rescale_offsets` заменяет переменные с байтовым смещением индексом. `interproc.py` (`link_types`, после `prepare` всех функций, до печати): типы параметров ↔ аргументов, вложенные структуры по `p + c` в аргументе, структуры на стеке и глобальные структуры. Указатели на указатели — `VarInfo.ptr_elem` в `types.py`. Подробно в `tests/structs/README.md`.
8c. `libc.py`: прототипы распространённых функций C. Число аргументов printf/scanf считается по строке формата (lcc дублирует variadic-аргументы в стековую область, иначе они видны как лишние), аргументы `char *`/`%s` делают переменную указателем на `char`, объявления в заголовке берутся отсюда.
9. `emit.py`: печать C и заголовок с хелперами (`__ROL4__`, `__smulh`…).
10. `parallel.py`: два прохода по функциям (сводки; подъём, анализ и структурирование) идут в процессах-исполнителях (`os.fork`, по каналу на каждый; потоки не помогли бы из-за GIL). Результаты возвращаются через pickle и собираются в исходном порядке. `objdump`-функции передаются ссылкой (`persistent_id`). Прототипы вызываемых функций (`Context.add_proto`, зависят от порядка) исполнитель записывает, а родитель повторяет по порядку функций. Функция, исполнитель которой упал или результат которой не сериализуется, пересчитывается в родителе. Межфункциональные типы (`link_types`) и печать остаются в родителе.

Скорость. `analysis.collect` (все определения и использования) раньше пересчитывался после каждой подстановки в `propagate`/`dce`/`merge_selects`, и это давало квадратичное время. Теперь `DefUse` пересканирует только изменённые блоки, а `propagate` ведёт рабочий список: отвергнутая переменная перепроверяется, только если изменился блок, от которого зависел отказ. Порядок выбора остался прежним (куча по позиции в `defs`), поэтому вывод тот же. `Expr.walk` возвращает список (явный стек вместо вложенных генераторов). `simplify` останавливается после прохода, в котором `simp` ничего не переписал.

`ir.py` содержит все классы выражений (`Const, Reg, Var, Load, Select, Call, Intr…`) и операторов (`Assign, Store, Branch, Switch, Return…`).

## Особенности e2k, которые важно помнить

- ШК содержит до 16 слов: ALS/ALES в каналах `,0`…`,5`, AAS, LTS. Всё внутри ШК выполняется параллельно.
- Предикация: `? %predN` / `? ~%predN`; сравнения `cmp*sb/db`, `fcmp*`; локальные `@pN` в PLU.
- Переходы: `disp %ctprN` готовит переход, `ct`/`call ..., wbs = N`/`return %ctpr3` его выполняют. `ibranch` означает прямой переход.
- Регистровые окна (`setwd`, `setbn`), вращаемые `%b[N]`.
- Спекулятивные загрузки (`,sm`), APB/AAU (`aaurw*`, `staa*`, `ldaa*`, `incr`), аппаратные циклы (`loop_mode`, `%NOT_LOOP_END`, `abn`, `alc`, `%pcnt`).
- Модель аппаратного цикла в `lift.py`: `rwd X,%lsr` → `lc = lcnt + ecnt`, `pc = pcnt`; `alc` → `lc -= 1`, `pc -= (pc != 0)`; `%NOT_LOOP_END` → `lc != 0` (после декремента), `%pcntN` → `pc <= N`, `%MLOCK` → 1 (путь пересчёта из перечитанной загрузки). `abn` → параллельный сдвиг вращаемого окна `N(i) := N(i-2)` при статических именах; `abp` → `pred[i+1] := pred[i]` в окне `setbp psz`. Условия `ct` и предикатного `call` читают состояние до ШК: перезаписываемые регистры снимаются в начале ШК.
- AAU/APB: `aaurw*` → `aad/aasti/aaincr`; `staa*`/`ldaa*` → store/load по `aad + aasti + lit`, `incr` → `aasti += aaincr * размер`. Программа FAPB (ШК из `apb`, выбирается `ldisp %ctpr2`) разбирается в `Lifter._scan_fapb`; `bap` задаёт `apbbase/aaldi/apbinc` областей, `mova*` → загрузка `base + aaldi + ind`, `am=1` сдвигает `aaldi`.
- Упакованные операции (`paddw`, `pcmpgtw`, `pfadds`, `pshufb`…) → хелперы `__paddw`… в заголовке (`emit.HEADER`), вывод компилируется.
- Составные операции: `X_sub s1,s2,s3 = s3 - (s1 X s2)`, `X_rsub = (s1 X s2) - s3` (qemu `e2k_2stage_*`); `getf_X s1,s2,s3 = s3 X getf(s1, s2)`, `getf_rsub = getf - s3`, `getf_andn = s3 & ~getf` (qemu `e2k_2stage_getf_*`).
- Спекулятивные загрузки (`ld*,sm`, `Load.spec`) lcc выносит выше проверки указателя на NULL. Через указатель, который сравнивается с 0, такая загрузка печатается как `__SPEC(p, x)` (0 для адресов < 4096), иначе C-вывод падал бы там, где e2k получает диагностическое значение.
- Литералы с релокацией (`R_E2K_64_ABS_LIT`): в .o на месте литерала лежит адрес относительно секции (значение символа + addend), 64-битный литерал занимает два слога, старшая половина первой. Порядок литералов в ШК не совпадает с порядком операндов, и две операции могут делить один слог (`addd 0, gtab` и `ldw 0, gtab` при одной релокации). Поэтому `lift.read` сопоставляет операнд с релокацией по значению на месте (`Resolver.lit_inplace`), а не по порядку.
- PIC/PIE: `rrd %ip` даёт адрес текущей ШК (qemu `sregs.ip`), lift превращает его в константу, дальше `ip + k` сворачивается в адрес. Загрузка из слота `.got` заменяется тем, что туда кладёт загрузчик (`got_value` по `.rela.dyn`/`.rela.plt`: `R_E2K_64_JMP_SLOT` 63 и `R_E2K_64_ABS` 50 → символ, `R_E2K_64_RELATIVE` 65 → константа, `R_E2K_64_COPY` 64 — копия данных в `.bss`). Вызов `ldd [ip+k]` → `movtd` → `call` так получает имя; имена вызовов, найденные после оптимизации, передаются в следующий раунд `lift_function` (`named_calls`), чтобы число аргументов бралось из прототипа. Версии символов (`stderr@GLIBC_2.2`, `free@plt.got`) при печати отбрасываются.
- LSR: `lcnt[31:0] ecnt[36:32] vlc[37] pcnt[52:48] strmd[59:53] semc[60]`; конец цикла `vlc && lcnt<2 && ecnt==0`.
- Записи в ШК с `loop_mode`: разрешены при `semc || pcnt == 0 && !(loop_end && strmd <= k)` (qemu `translate-cds.c`), `k` — номер записи в последней итерации. В lift это охрана `Intr st_enbl(...)`, сворачивается в `simplify`. lcc ставит `strmd` = числу записей за итерацию и `pcnt = 0`.

## Тесты

- `tests/t1.c`, `tests/t2.c` → `*_O0/O1/O2.o`, `t2_exe`: базовые конструкции, switch и jump tables.
- `tests/arch/arch.c`: десять тестов на особенности архитектуры («столовые», спекулятивные загрузки, широкие команды, saxpy/dot, fib, clamp, find, fsel). `feat.py` показывает, какие возможности e2k встретились в каждой функции. В `README.md` описано, на что смотреть. `arch_O1.dc.c` и `arch_O3.dc.c` хранят текущий вывод декомпилятора, их удобно сравнивать после изменений.

- `tests/loops/loops.c`: 16 форм циклов, `-O0..-O3`. `tests/loops/unroll.c`: 13 циклов, которые lcc разворачивает, `-O1..-O3`. `tests/loops/difftest.py` — дифференциальный тест: исходник и декомпилированный код компилируются `gcc` (x86) и сравниваются на случайных входах. Наборы: loops, unroll, arch, t1, t2, structs, structs2, включая перекрывающиеся массивы. Файл декомпилируется целиком (типы выводятся по всем функциям), из вывода вырезаются тестируемые функции. Запускать после любых изменений: `python3 tests/loops/difftest.py`. Сейчас 312 сочетаний «функция × уровень», 130 800 прогонов, расхождений 0.

- `tests/structs/structs.c`: 12 функций со структурами (поля разных типов, выравнивание, список, массив в структуре, массив структур, вложенная структура), `-O0..-O3`, входит в difftest.
- `tests/structs/structs2.c`: 14 функций: указатели на указатели, вложенные структуры через вызов, массив фиксированной длины в структуре, структура на стеке, глобальные структура и массив структур. Сборка `tests/structs/build.sh structs2`.
- `tests/sigcheck.py` сравнивает сигнатуры декомпилированных функций с исходниками тестов (типы параметров и результата). Сейчас 769 из 798 позиций (96%) совпадают точно.
- `tests/real/survey.py`: настоящие программы (8 утилит glibc из `$LCC/fs/usr/bin`, PIE). Считает функции, отказы, функции с `__e2k_*`, `goto`, ошибки gcc и время; эталона нет, смотреть на тренд. Сейчас 97 функций, 0 отказов, 12 с `__e2k_*`, 343 `goto`, 59 ошибок gcc, около 24 с на двух ядрах (v9: 95 с). Подробнее в `tests/real/README.md`.

Прогона в qemu-e2k пока нет. Функции с `__e2k_*`/`__asm__` difftest не проверяет (сейчас это `dec_chars` и `sum_xor` из `unroll.c` на `-O3`).

## Состояние

- Все тесты (loops, arch, t1, t2 на всех уровнях) декомпилируются без `__asm__`/`__e2k_*` и совпадают с исходником в difftest. Это включает конвейеризованные циклы (вращаемые `%b[]` и `%pred`, LSR, `%pcnt`, `%MLOCK`), AAU, APB и векторизацию -O3 (упакованные операции переведены в скалярные, счётные циклы печатаются как `for (i = 0; i < n; ++i)`).
- Типы: указатели с типом элемента, `int`/`long`/`unsigned`, `char`/`short`, `float`, указатели на функции, `void` по вызывающим в том же файле, прототипы libc. Структуры восстанавливаются по указателям, на стеке и глобальные, указатели на указатели (`char **`, `int **`, `struct s **`), см. `tests/structs/README.md`. Структура из одинаковых полей печатается массивом. Не восстанавливается `void` у функций без вызывающих в файле (по коду результат неотличим от «мусора» в `%r0`), а переменная, в которую слиты параметр и результат через охраняемые присваивания (`whilebrk -O2`), остаётся `long`.
- Устойчивость: каждая функция декомпилируется под бюджетом времени (`Decompiler.func_timeout`, `--timeout`, по умолчанию 60 с на анализ и столько же на печать; SIGALRM, только в главном потоке), ошибка или превышение дают комментарий `// f: decompilation failed` вместо функции. Сбой `link_types` стоит только межпроцедурных типов (`_fallback_structs`), сбой объявлений — только заголовка. Циклы до неподвижной точки в AST-проходах ограничены 1000 раундами.
- Развёрнутые циклы `-O2` сворачиваются в один (`reroll.py`); версии `-O3` с разворотом в 4 раза, хвостами 2 + 1, несколькими накопителями и широкими загрузками остаются как есть.
- Не сделано: свёртка конвейеризованных рекуррентностей, где загрузки идут на несколько итераций вперёд (`inf_loop`, `while_cond`, `saxpy` при `n < 16`), и деление 64-битных «хвостов» векторных циклов. Подробнее в `tests/loops/README.md`.

## Соглашения

- Только стандартная библиотека Python, никаких зависимостей.
- Новая операция поднимается в `lift.py`. Если семантика неочевидна, сверяться с qemu (`translate-al-c2.c`) и binutils (`e2k-opc.h`), а не угадывать.
- После изменений перегенерировать `tests/arch/arch_O*.dc.c` и посмотреть diff.
- Общение с пользователем ведётся на русском.
